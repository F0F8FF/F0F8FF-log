LLM 제품을 만들다 보면 항상 같은 질문에 부딪힙니다. **"우리 모델이 잘하고 있는지 어떻게 측정하지?"**
사람이 매번 채점할 수는 없어서 LLM을 심판으로 쓰는데, 순진하게 만들면 두 가지 함정에 빠집니다.

1. **위치 편향** — A/B 비교에서 단순히 먼저(또는 나중에) 나온 답을 선호
2. **후광 효과** — 한 번에 여러 기준을 매기면 점수가 서로에게 끌려감

이 프로젝트는 두 함정을 엔지니어링으로 제거하고, 판정의 신뢰도를 사람 평가와의 일치율로 정량 검증합니다.

- 저장소: [F0F8FF/llm-judge](https://github.com/F0F8FF/llm-judge)
- 데모: [llm-judge-sigma.vercel.app](https://llm-judge-sigma.vercel.app)
- 스택: Next.js · TypeScript · OpenAI Structured Output · Langfuse

## 평가 모드 1 — 기준별 채점

정확성·관련성·완결성·명확성·안전성을 각각 **독립된 LLM 호출**로 1~5점 채점합니다.

한 번의 호출로 모든 기준을 매기면 기준 간 후광 효과가 생겨서, 기준당 호출을 분리해 점수의 독립성을 확보했습니다.
호출 수와 비용은 늘어나지만 그만큼 신뢰도를 얻는 트레이드오프입니다.

## 평가 모드 2 — A/B 비교 + 위치 편향 제거

두 답변을 비교하되 **순서를 바꿔 두 번** 평가합니다.

```
판정 1: [A, B] 순서로 비교 → 승자
판정 2: [B, A] 순서로 비교 → 승자

두 판정이 같은 답을 가리킬 때만 최종 승자로 인정
결과가 뒤집히면 → 편향 감지 → 무승부 처리
```

순서를 바꿔도 같은 답을 고르면 위치 편향이 없다고 볼 수 있고, 뒤집히면 그 판정은 신뢰할 수 없다고 판단합니다.

## 기술 의사결정

- 출력은 **Structured Output**(json_schema strict)으로 강제해 파싱 실패를 0으로 만들었습니다
- **temperature=0**으로 평가의 재현성을 확보했습니다
- 심판이 믿을 만한지는 주장이 아니라 **사람 평가와의 일치율**로 증명해야 한다고 봤습니다

## 보정(Calibration) 평가

`npm run eval`로 사람이 라벨링한 A/B 데이터셋에 판정을 돌려
**사람 일치율**과 **편향 일관성**을 출력합니다. 심판 자체의 품질을 측정하는 단계입니다.
