도구를 사용해 스스로 작업을 해결하는 LLM 에이전트입니다.
에이전트는 "돌아간다"만으로는 부족하고, **관측 가능해야 하고 실패해도 복구해야 하며 품질을 측정할 수 있어야** 운영할 수 있다고 생각해서 그 세 가지를 중심으로 만들었습니다.

- 저장소: [F0F8FF/agent-system](https://github.com/F0F8FF/agent-system)
- 데모: [agent-system-cyan.vercel.app](https://agent-system-cyan.vercel.app)
- 스택: Next.js · TypeScript · OpenAI function calling · Langfuse

## 세 가지 축

- **투명한 추론 트레이스**: 생각 → 도구 호출 → 관측의 모든 단계를 실시간 스트리밍으로 표시
- **실패 복구**: 도구 오류를 모델에 다시 넘겨 스스로 교정하게 하고, 모델 호출은 재시도
- **품질 게이트**: 라벨링된 작업셋으로 성공률·평균 스텝·비용을 측정해 배포 전 회귀 탐지

## ReAct 루프

```
1. 도구 목록과 함께 모델 호출 (tool_choice: auto)
2. 모델이 도구를 호출하면 → 실행 → 결과를 tool 메시지로 추가 → 다시 모델 호출
3. 도구 호출이 없으면 → 그 응답이 최종 답변
4. 매 단계를 NDJSON 이벤트로 스트리밍
   step_start / thought / tool_call / tool_result / final / usage
```

구현한 도구는 산술 계산기, 위키피디아 요약 검색, 현재 시각 세 가지입니다.

## 기술 의사결정

**도구는 절대 throw하지 않는다.** 오류를 예외로 던지면 루프가 끊기지만,
`error:` 문자열로 반환해 컨텍스트에 환류하면 모델이 그걸 읽고 다음 시도에서 스스로 교정합니다.
실패 복구를 별도 로직 없이 얻을 수 있었던 부분입니다.

**계산기는 화이트리스트 검증.** 표현식을 그대로 평가하면 임의 코드 실행이 되므로
숫자와 연산자만 허용한 뒤 평가하도록 했습니다.

**MAX_STEPS 하드캡.** 에이전트에서 가장 무서운 건 무한 루프로 인한 비용 폭증이라,
최대 스텝을 못 넘게 막고 스텝·토큰·비용을 모두 계측합니다.

**스트리밍은 토큰이 아니라 트레이스 이벤트.** 단계별 타임라인 UI를 만들려면
구조화된 이벤트가 필요해서 커스텀 NDJSON 프로토콜을 정의했습니다.

## 회귀 평가

`npm run eval`로 라벨링된 작업셋을 실행해 **성공률 / 평균 스텝 / 평균 지연 / 총 비용**을 출력합니다.
프롬프트나 도구를 바꿨을 때 성공률이 떨어지는지 배포 전에 확인하는 용도입니다.
